# 005 — AGENTS.md 作为项目级上下文锚点

## 状态

已接受（第七阶段）

## 背景

本插件的规范分两层存放，两层要回答不同的问题：

- **规范全文**（`skills/dsh-dev-workflow/SKILL.md`，212 行 / 10602 字符）是本插件的价值载体，
  但它**不能常驻**——全文每轮是 2600 token 量级的开销（[003](003-summary-plus-on-demand.md)）。
  它只能按需读取，而按需读取意味着模型必须先**知道**它存在、并且愿意去读。
- **一行技能目录条目**（`t('skill.summary')`）是插件在模型上下文里唯一的常驻痕迹。
  一行话足以说「有这个技能」，不足以说清这个项目的规则（分支怎么命名、提交信息什么格式、
  哪两份文件必须成对改）。

于是出现一个空隙：**「必须先知道」和「不必每轮付费」之间的那段内容放在哪里？**

DSH 提供了一个正好填这个空隙的机制。按 `.dev-docs/DSH-API-NOTES.md:630` 的核对结论，
`@deepseek-ai/dsh-agent-instructions`（dsh-base 已启用）在进入项目时自动读取：

| 事实 | 值 |
| --- | --- |
| 加载对象 | `$DSH_HOME/AGENTS.md` **加上**项目链（project root → cwd，大致到具体，broad-to-specific） |
| 项目根标记 | `.git` |
| 候选文件名 | `AGENTS.md`、`CLAUDE.md`；本地覆盖 `AGENTS.local.md`、`CLAUDE.local.md` |
| 去重 | 内容相同的文件只渲染一次（用户级与项目级重复时不重复付费） |
| 字节预算 | `maxBytes` 默认 **65536**（可由配置改小） |
| 更新粒度 | **不持续 watch 外部编辑**；成功的 fs 操作会发现更深的文件，session resume 重对基线 |

也就是说：**项目里有一个每轮都在、但由项目自己拥有的上下文位。** 它不花插件的预算，
也不需要模型主动去读。

## 决定

**AGENTS.md 是本仓库的上下文锚点，SKILL.md 是插件的规范全文。两者分工固定，不互相替代。**

- **AGENTS.md 放「每一轮都必须成立的稳定规则」**：项目定位（插件而非模式）、核心原则
  （按动作自动触发、常驻摘要 + 按需全文、技能为主、平时安静）、关键约束（分支命名、
  Conventional Commits、文档与代码同 PR、CHANGELOG `[Unreleased]` 常驻顶部、
  README / locale / SKILL 三对文件必须同时改、ESM-only、工具名合同、API 以本机实际版本为准）、
  常用命令、以及「详情见哪份文档」的入口清单。**不放进度状态，不放会变的东西。**
- **SKILL.md 放「做这件事的时候才需要读的规范」**：分支模型的完整说明、提交信息规范、
  原子提交、PR 与质量门禁、文档同步、版本发布、CHANGELOG 维护、安全操作、自动触发时机。
  它随包发布，面向任何安装本插件的用户，**不是**这个仓库的私有内容。
- **进度状态放 `.dev-docs/PROGRESS.md`**（已被 `.gitignore` 忽略），不进 AGENTS.md——
  它每个阶段都变，而每轮常驻的内容一变，成本与稳定性都要重算。
- **AGENTS.md 是唯一主文件**：其他 AI 工具（Claude Code 等）通过软链接或构建脚本同步
  `CLAUDE.md` 等副本，不手动维护多份。同一个内容在项目链里只会被渲染一次，所以副本不额外付费，
  但也因此完全可以做成链接。
- **预算是硬边界**：AGENTS.md 必须留在 65536 字节预算的一小部分里（当前 3291 字节）。

## 后果

**好的后果**

- **空隙被填上，而且不花插件的 token 预算。** 模型进入项目就带着「这个仓库有规范、
  细节在 SKILL.md」这个认知，插件的常驻增量仍然只有 903 / 572 字符
  （[docs/TOKEN-BUDGET.md](../TOKEN-BUDGET.md)）——因为规则住在项目文件里，不是住在插件里。
- **规则与它描述的项目住在一起。** 分支命名、提交格式这类规则是**这个仓库**的约定，
  不是插件的属性。放在 AGENTS.md 里，它就能随仓库演进、被 code review、被 blame。
  插件装到别人仓库时不会把本仓库的约定强加于人。
- **模型不必先做选择。** 「要不要读一份规范」这个决定被消掉了：稳定规则每轮自动在场，
  只有完整流程需要主动读。
- **单一事实源。** 主文件只有一份，其余工具的文件是链接或生成物。

**坏的后果**

- **AGENTS.md 只对本仓库生效，不随包分发。** `package.json` 的 `files` 白名单里没有
  `AGENTS.md`（也没有 `docs/`）。安装本插件的用户拿到的是 SKILL.md，
  看不到这份锚点文件，也就不会有与之等价的每轮提示——他们的兜底是技能目录那一行。
- **预算会被别人分走。** 65536 字节是所有项目链文件共享的上限。本仓库现在用掉 3291 字节
  （1947 字符 ≈ 990 token，按 TOKEN-BUDGET.md 同一口径估算），约占 5%；
  但 AGENTS.md 每长一段，每轮成本就长一段，因此它和工具描述一样属于**成本改动**。
- **不是每轮都重新读。** 机制不 watch 外部编辑：中途改了 AGENTS.md，本次会话可能仍用旧内容。
  写错规则的代价是**静默**的——模型会照着错的做，直到某个检查报错。
- **会与 SKILL.md 漂移。** 同一个规则在两处出现时，两处的措辞必然分岔。缓解办法是分工而非同步：
  AGENTS.md 只写规则本身的一句话，展开与边界留给 SKILL.md。

**中性后果**

- 新增稳定规则时，要判断它属于哪一层：每轮都成立 → AGENTS.md；做事时才需要 → SKILL.md。
  两者都不是 → `docs/`。
- **改 AGENTS.md 必须同时看 SKILL.md 是否也该改**，反之亦然。这条约定靠人工审查，CI 不校验。
- `.dev-docs/`（包含 `PROGRESS.md` 与 `prompt.md`）是本机私有目录，克隆仓库后不一定存在；
  AGENTS.md 里引用它时必须说明这一点。
- 其他工具的文件名以「当前 DSH 实际支持的候选名」为准，不写死在本 ADR 里——
  候选名单是 DSH 的行为，不是我们的决定（依据同上表）。

## 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 稳定规则只写在 SKILL.md 里 | 技能是可以被忽略的：模型不读技能就不知道有规范，而「必须先知道」正是这份文件要解决的问题。技能目录那一行只够说「有这个技能」，不够说清规则 |
| 把规范全文放进 AGENTS.md | 10602 字符 ≈ 2600 token/轮（[003](003-summary-plus-on-demand.md)），比常驻预算高一个数量级；而且 AGENTS.md 会被任何项目改写，全文放进去等于把规范的定义权交给每个使用方 |
| 用 `systemPrompt` 服务注入规则 | 这是插件的正式常驻通道，但它注入的是**插件**的话，不是**本仓库**的话。规则属于仓库（`AGENTS.md` 可以被 review、被 blame），插件不该替用户的项目宣布分支命名规则 |
| 靠技能目录那一行承担全部提示 | 一行 `t('skill.summary')` 只能写「在提交、建分支或改文档之前先读它」，写不下 Conventional Commits 的格式或「README 双语必须同步」这类约束 |
| 把进度状态写进 AGENTS.md | 进度每阶段都变，写进去会让每轮常驻内容随阶段刷新，也让「稳定规则」与「当前状态」混在一处——与 003 的原则（常驻内容应是与长度解耦的常量）冲突 |
| 每个 AI 工具各维护一份手工副本 | 同一内容在项目链里只渲染一次，因此副本不省任何钱，却会漂移。用软链接或构建脚本同步，主文件只有 `AGENTS.md` |
| 依赖 `CLAUDE.md` 等其它候选名做主文件 | 候选名是 DSH 的实现细节（可能随版本变化）；主文件应当是大多数工具都会读的那一个，其余作为链接 |
