# 003 — 常驻摘要 + 按需全文，不每轮注入完整规范

## 状态

已接受（2026-10）

## 背景

本插件分发的规范全文有两份：`skills/dsh-dev-workflow/SKILL.md` 与 `SKILL.zh.md`。它是本插件
主要的价值载体，也是**唯一**会随每条请求反复付费的东西——只要它进了常驻上下文，用户每问
一句话都要重付一次。两份正文的当前体量与复算方法见
[docs/TOKEN-BUDGET.md](../TOKEN-BUDGET.md)。

约束是硬的：`.dev-docs/prompt.md` 与 `AGENTS.md:17` 都写着「常驻增量控制在几百 token 量级」。
规范全文有 20000 字符量级，按非 CJK 的 4 字符/token 粗估就是 5000 token 量级的开销，比验收线
高一个数量级。

问题因此不是「规范放哪里」（那个问题由 [001](001-skill-first-approach.md) 回答，
答案是技能而不是系统提示），而是**一份常驻内容里到底该有多少东西**：

- DSH 的 `ctx.tools.register` 注册的工具定义是常驻的（名字、描述、参数 schema）。
- `ctx.skills.registerProvider` 的目录条目（`name: description`）是常驻的。
- 技能正文经 `SkillProvider.get()` 读取，**不是**常驻的。

也就是说「常驻」与「可读」在 DSH 里是两个独立的档位，而规范正文需要的是后者。

## 决定

**常驻的只有两样：两个工具的定义，和一行技能目录条目。** 规范全文按需读取。

具体到 `src/index.ts` 的 `activate()`：注册两个工具、一个技能 provider、
一行 `t('skill.summary')` 作为目录条目。除此之外不注册任何常驻内容。

目录行刻意只有一句话，不带章节摘要、不带规则清单。

## 后果

**好的后果**

- **常驻成本与规范长度解耦。** 规范从 200 行长到 2000 行，每轮付的还是那一行目录条目。
  实测常驻增量 903 字符（`en-US`，≈226 token）/ 572 字符（`zh-CN`，≈240 token），
  落在「几百 token」这一档内（[docs/TOKEN-BUDGET.md](../TOKEN-BUDGET.md)）。
- **规范可以写全。** 因为不常驻，它不必被压缩成口号——边界条件、示例、反面例子都能留住。
  反过来，如果它常驻，第一个被砍掉的就是这些边界条件。
- **`mode: 'off'` 时成本为零。** 不注册就没有 `tools`/`skills` 条目，常驻增量正好是 0。
  这是这一档存在的理由，也是它在 `src/index.ts` 里被实现成「注销注册」而不是
  「注册但静默应答」的原因。
- **成本不随会话增长。** 插件不监听 `message/*` 之类的事件往上下文里塞内容，
  所以常驻部分在整个会话里是个常量。

**坏的后果**

- **模型可以不读。** 系统提示里的内容无法被忽略，一行目录条目是可以的。
  这是这套分层的真实代价，只能靠把 `skill.summary` 写成行动指令（「在提交、建分支或改文档
  之前先读它」）来缓解，不能消除。
- **读一次就是一次额外的工具调用与一次上下文增长**（当前正文体量见
  [docs/TOKEN-BUDGET.md](../TOKEN-BUDGET.md)）。
  在长会话里反复读同一份正文是不划算的；provider 的正文缓存只管到进程内。
- **观测值没人替你守。** CI 不校验这个数字——它是观测值，不是能机械断言的门槛。
  常驻增量从几百涨到几千时不会报错，只会慢慢变贵。

**中性后果**

- `docs/TOKEN-BUDGET.md` 成为一份活文档：任何改动常驻内容的 PR 都应重跑
  `.dev-docs/_probe/tokens-3a.mjs` 并把新数字写回去。
- 工具描述必须短。改工具描述等于改常驻成本，评审时要把它当成本改动看，而不是文案改动。
- 同一时刻只有一种 locale 生效（字典按需解析、只在语言变化时重建），于是常驻的只有一份
  目录行、一份工具描述，而不是两套。

## 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 规范全文常驻（系统提示或工具描述） | 两万字符量级的正文 ≈ 5000 token/轮，是验收线的十倍。工具描述同样是每轮常驻，写进描述只是把同样的成本挪到更隐蔽的位置 |
| 把规范压成几十行常驻 | 压缩必然丢边界条件，而规范的价值恰在边界条件上（「`--no-verify` 默认 `ask` 而不是 `deny`，因为它是逃生通道」这类句子压不掉）。压缩版还会与 SKILL.md 形成两个事实源，随后必然漂移 |
| 常驻一份「章节摘要」，正文按需 | 目录行会从 137 字符涨到上千字符，等于把成本换了个名字保留；而摘要能不能替代正文取决于读者，模型仍要为了细节去读全文，两头都不省 |
| 用事件监听把规范按需塞进上下文 | 属于「事件轰炸」：模型没在提交时也会收到内容，成本随会话增长，与「成本是常量」直接冲突 |
| 注册两个技能（英文一个、中文一个） | 目录条目变成两行（常驻翻倍），模型还要自己选。正文选哪一份取决于会话语言，不是模型该操心的事 |
