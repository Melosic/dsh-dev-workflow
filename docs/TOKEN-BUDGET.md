# 常驻 Token 预算

本文件回答一个问题：装上 dsh-dev-workflow 之后，**每一条请求**要多付多少 token？

答案是几百量级，与用户消息长度无关。本文件给出这个数字是怎么来的、怎么复算、
以及哪些设计选择把它压在这个量级上。

## 常驻的是什么

插件挂载后进入模型上下文的只有两项，都在 `src/index.ts` 的 `activate()` 里注册：

| 来源 | 内容 | 说明 |
| --- | --- | --- |
| `ctx.tools.register` | 两个工具的 JSON 定义 | 工具名、描述、参数 schema |
| `ctx.skills.registerProvider` | 一行技能目录条目 | `name: description`，`description` 取自 `t('skill.summary')` |

**规范全文不在其中。** `SKILL.md` / `SKILL.zh.md` 只有在模型主动打开技能时才被读取
（`SkillProvider.get()`），那是按需成本，不是常驻成本。

## 实测数字

在仓库根目录运行：

```bash
pnpm build
node .dev-docs/_probe/tokens-3a.mjs
```

（该脚本是本地探针，`.dev-docs/` 不纳入版本控制。测法本身记录在此，任何时候都可以
用同样的口径复算。）

本机实测结果：

| 语言 | 工具定义字符数 | 目录行字符数 | 常驻合计字符数 | 估算 token |
| --- | --- | --- | --- | --- |
| `en-US` | 766 | 137 | 903 | ≈ 226 |
| `zh-CN` | 522 | 50 | 572 | ≈ 240 |

Token 估算口径（脚本内的 `estimate()`）：非 CJK 字符按 4 字符/token，CJK 字符按
1 字符/token。这是一个保守的上界——中文目录行短但每字一个 token，所以两种语言的
估算值落在同一档；真实分词结果通常在两者之间。

**结论：常驻增量在 200–250 token 量级，符合「几百 token」的验收标准。**

## 按需成本

| 文件 | 字符数 | 行数 |
| --- | --- | --- |
| `skills/dsh-dev-workflow/SKILL.md` | 20367 | 418 |
| `skills/dsh-dev-workflow/SKILL.zh.md` | 10289 | 350 |

这份成本只在模型决定读规范时支付一次，并且每个会话读一次就够。它不受「每轮注入」
影响，也不随对话轮数增长。

## 汇总

| 层级 | 时机 | 量级 |
| --- | --- | --- |
| 两个工具定义 | 每轮常驻 | ~520–770 字符 |
| 技能目录行 | 每轮常驻 | ~50–140 字符 |
| 规范全文 | 按需，每个会话至多一次 | ~10300–20400 字符 |
| `mode: 'off'` 时 | 永不 | 0 |

`mode: 'off'` 时插件不注册任何东西，常驻增量为**零**——这是这一档存在的理由，也是
它在 `src/index.ts` 里被实现成「注销注册」而非「静默应答」的原因。

## 设计约束

这几条不是风格偏好，它们直接决定了上面的数字：

1. **规范放在技能里，不放在系统提示里。** 全文按需读取，因此无论规范多长，常驻成本
   不变。
2. **只说一句话。** 目录行只有 `skill.summary` 一句，不附带章节摘要、不附带规则清单。
3. **工具描述保持精简。** 两个工具的描述都是一句话；把规则写进描述会让它每轮重复付费。
4. **不加事件监听式的注入。** 插件不监听 `message/*` 之类的事件往上下文里塞内容，
   常驻成本因此不随会话增长。
5. **locale 在加载时解析一次。** 于是只有一份目录行、一份工具描述常驻，而不是两套。
   语言切换通过 `SkillProvider.get()` 的动态读取实现，不通过重复注册实现。

第 5 条有一个可观察的后果：工具描述随语言变化（中文描述更短，所以 `zh-CN` 的
`toolsChars` 更小），而 `resourceBase` 与技能正文则各自独立地跟随 `currentLocale()`。

## 变更时怎么保持这个预算

改动常驻内容时（新增工具、改 `skill.summary`、改工具描述），重新跑一次上面的脚本，
把新数字更新到本文件。CI 不校验这个数字——它是观测值，不是可机械断言的门槛。真正
需要守住的是那份量级判断：如果某次改动把常驻增量从几百推到几千，那说明有内容被放错
了层，应该回到技能正文里。
